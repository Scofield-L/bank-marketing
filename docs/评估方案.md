# 评估方案（Evaluation Scheme）

## 1. 评估目标

客观衡量各模型的分类性能，选出最优模型。重点：由于**类别不平衡**（正例约 11%），不能只看「准确率」这一个指标。

## 2. 为什么不能只看准确率

正例（`yes`）仅约 11%。如果模型把所有样本都预测为「不订阅 `no`」，准确率也能达到约 89%，但它**一个正例都没召回**，完全没有业务价值。因此必须结合精确率、召回率、F1、AUC、PR-AUC 综合评估。

## 3. 评估指标定义

先定义混淆矩阵四要素（正类 = `yes` 订阅）：

| 记号 | 含义 |
|------|------|
| TP | 预测 `yes` 且实际 `yes` |
| FP | 预测 `yes` 但实际 `no` |
| FN | 预测 `no` 但实际 `yes` |
| TN | 预测 `no` 且实际 `no` |

| 指标 | 公式 | 说明 |
|------|------|------|
| 准确率 Accuracy | (TP+TN) / (TP+TN+FP+FN) | 受不平衡影响大，仅作参考 |
| 精确率 Precision | TP / (TP+FP) | 预测为正例里，真正例的占比 |
| 召回率 Recall | TP / (TP+FN) | 真正例里被找出的比例（**银行更看重，别漏掉潜在客户**） |
| F1 | 2·P·R / (P+R) | 精确率与召回率的调和平均 |
| AUC-ROC | ROC 曲线下面积 | 整体排序能力，不受阈值影响 |
| PR-AUC | PR 曲线下面积 | **不平衡场景下比 ROC 更敏感**，作主参考 |

## 4. 评估流程

1. 固定 `train_test_split`（`stratify=y`，`random_state=42`），保证所有模型可比。
2. 对每个模型：训练 → 预测测试集 → 得到**预测标签 `y_pred`** 和**预测概率 `y_prob`**。
3. 计算各指标，汇总成对比表。
4. 画 ROC 曲线、PR 曲线、混淆矩阵。
5. 阈值调优：在 PR 曲线上选合适阈值，权衡精确率与召回率。
6. 交叉验证（5-fold）验证结果稳定性。

## 5. 需要成员 B 提供的产出（关键对接点）

为画 ROC/PR 曲线、做阈值调优，**B 必须输出**：

- 测试集的**预测概率 `y_prob`**（`predict_proba` 的正类概率），**不只是预测标签**；
- 各模型的**预测标签 `y_pred`**；
- 树模型的**特征重要性**；
- 结果统一保存（CSV / `.npz`），方便组长 C 读取。

> 如果 B 只给了预测标签而没有概率，就画不了 ROC/PR 曲线、也做不了阈值调优——这是最容易出问题的对接点。

## 6. 模型对比方案

对比对象：

- 模型：LR（基线）、DT、RF、XGBoost；
- 不平衡处理：原始 / SMOTE / 欠采样 / `class_weight` 四种组合；
- 字段口径：主实验（仅排除 `duration`）vs 对照实验（额外排除 `campaign`/`day`/`month`），验证字段泄漏对结论的影响。

产出：

- 一张**综合对比表**（所有模型 × 所有指标）；
- **ROC 曲线叠加图**、**PR 曲线叠加图**各一张。

## 7. 阈值调优

- 默认阈值 0.5 不一定最优。
- 在 PR 曲线上找「精确率与召回率平衡」的阈值，或按业务（银行更重视召回）选阈值。
- 展示不同阈值下精确率/召回率的变化曲线。

## 8. 最终模型选择标准

- **主指标**：AUC / PR-AUC（不平衡场景最可靠）。
- **辅指标**：F1 与召回率（业务上希望不漏掉潜在客户）。
- 兼顾：模型复杂度、可解释性（特征重要性 / SHAP）、训练时间。

## 9. 报告呈现

- 一张综合对比表 + ROC/PR 双图 + 混淆矩阵 + 阈值调优图。
- 结论：推荐「XX 模型」，理由（AUC 最高 / F1 最好 / 兼顾业务）。
