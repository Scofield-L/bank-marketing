# 技术路线（Technical Route）

## 0. 设计原则（重要）

- **定死「协议」**：任务、数据、划分方式、评估指标必须固定，保证所有方案在同一标准下公平对比。
- **开放「选型」**：具体算法 / 方法不预先定死，列为**候选方案池**，第 2 周通过对比实验、用评估指标选出最终方案。
- 好处：避免先入为主；且报告可展示"列候选 → 对比实验 → 选最优"，更贴合作业要求③④。

---

## 1. 任务定义（确定项）

| 项目 | 内容 |
|------|------|
| 任务类型 | 二分类（监督学习） |
| 数据集 | UCI Bank Marketing Data Set，约 45,211 条 |
| 特征 | 16 个输入字段（bank-full；主实验排除 `duration`，实际用 15 个） |
| 目标变量 | `y`：客户是否订阅定期存款（`yes`/`no`） |
| 样本分布 | 正例约 11%，负例约 89%（类别不平衡） |

## 2. 整体流程（确定项）

```
数据收集 → 数据预处理 → 探索性分析(EDA) → 建模与选型实验 → 结果可视化 → 评估 → 报告/汇报
```

## 3. 确定项：必须固定的「协议」

### 3.1 数据与划分协议（成员 A）

| 项 | 固定值 / 原则 |
|----|--------------|
| 数据来源 | UCI Bank Marketing（bank-full.csv，16 输入字段） |
| 划分方式 | `train_test_split`，`stratify=y`，`random_state=42` |
| 字段口径（预测时点） | 主实验排除 `duration`；对照实验额外排除 `campaign`、`day`、`month`（见下） |
| 基础预处理 | `unknown` 缺失处理、异常值识别 —— 这些**动作必须做**，但具体编码/缩放方式开放（见候选池） |

**字段口径与泄漏说明**：预测假设为"银行决定联系后、通话完成前"。`duration`（通话时长）在通话后才可知，属目标泄漏，主实验一律排除。`campaign`（本轮联系次数，含最后一次）、`day`/`month`（最后一次联系日期）同样疑似"当次联系"信息，因此：

- **主实验**：仅排除 `duration`（其余字段保留，声明假设"决策时点已知联系次数与日期"）；
- **对照实验**：额外排除 `campaign`、`day`、`month`，验证结论是否稳健。

### 3.2 评估协议（组长 C）

- 指标固定：**主指标 PR-AUC / AUC**，辅以 F1、召回率（详见 `docs/评估方案.md`）。
- 所有模型必须用**同一划分、同一指标**对比，保证公平。

## 4. 候选方案池：待实验选型（第 2 周通过对比实验确定）

> 每项列出多个候选 + 选型标准，最终由实验数据决定，而非预先拍板。

### 4.1 类别编码

| 候选 | 说明 |
|------|------|
| One-Hot Encoding | 无序类别，模型通用 |
| Label Encoding | 树模型可用，简单 |
| Target Encoding | 高基数类别，可能过拟合，需验证 |

### 4.2 数值缩放

| 候选 | 说明 |
|------|------|
| StandardScaler | LR 等距离敏感模型需要 |
| MinMaxScaler | 有界缩放 |
| 不缩放 | 树模型（DT/RF/XGBoost）本身不敏感 |

### 4.3 类别不平衡处理

| 候选 | 说明 |
|------|------|
| 原始（不处理） | 作为基线对照 |
| SMOTE 过采样 | 合成少数类样本 |
| 随机欠采样 | 减少多数类样本 |
| `class_weight` | 代价敏感，无需改数据 |

### 4.4 建模算法

| 候选 | 角色 |
|------|------|
| 逻辑回归 LR | 基线（baseline） |
| 决策树 DT | 简单可解释 |
| 随机森林 RF | 集成、稳健 |
| XGBoost | 强基线，通常最优候选 |
| LightGBM（可选） | 速度快，可对比 |

### 4.5 调参策略

| 候选 | 说明 |
|------|------|
| GridSearchCV | 小网格穷举，稳妥 |
| RandomizedSearchCV | 大网格随机，省时 |
| 贝叶斯调参（可选） | 更高效 |

## 5. 选型机制（如何从候选池选定最终方案）

1. **第 2 周**：在统一评估协议下，对每个候选组跑对比实验。
2. 记录每个候选的指标，汇总成**对比表**。
3. 选定原则：
   - 主指标 **PR-AUC / AUC** 优先；
   - 兼顾 **召回率**（业务上不漏掉潜在客户）与**可解释性**；
4. 选定结果连同"对比过程"写入报告「模型对比 / 评估」章节。
