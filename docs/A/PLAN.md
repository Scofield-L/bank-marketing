# 成员 A 总体执行计划（PLAN）

> 依据：[分工执行计划](../分工执行计划.md)  
> 角色：数据 / 工程；主责数据收集、预处理、特征工程与代码整合。  
> 项目截止：2026-11-30 前；本文件记录计划，未勾选事项均表示尚未验收。

## 一、目标与职责边界

为银行定期存款订阅预测任务提供来源明确、处理可解释、划分可复现的数据，以及可供 B 建模、C 评估的统一代码基础。最终由 A 整合完整项目代码包，提供运行说明和依赖清单。

- **A 主责**：数据版本核对、数据质量检查、预处理实现、基础特征处理、数据划分、环境统一、代码整合和复现说明。
- **与 B 协作**：B 根据 EDA 提出特征构造与选择方案，A 协助落地并维护一致的数据接口；A 准备不平衡处理方案，B 主责模型对比与调参。
- **与 C 协作**：A 提供数据和预处理说明、复现材料及 AI 使用记录；B 向 C 交付模型预测，C 主责评估、报告定稿、PPT 和视频。

现有分工文档与 `data/README.md` 对数据文件、样本数、特征数和 `pdays` 含义的描述存在混用风险。正式处理前，以所选文件及对应官方说明为准核实，不能直接把“约 45,211 条、20 个特征”当作已验证结果。

- [ ] 与 B、C 统一选用的数据文件及版本，区分完整文件与抽样文件。
- [x] 记录来源 URL、下载日期、文件名、校验值、实际行列数、分隔符及目标列。
- [x] 核实数据规模满足不少于 5,000 条的要求；若不满足，改用完整数据文件。
- [x] 核实特征列表、`unknown` 含义、`pdays` 特殊值及目标变量取值。
- [ ] 明确预测发生在通话前还是通话后；`duration` 是否纳入主实验由三人统一，并记录理由。
- [ ] 与 B、C 确认划分方式、随机种子和统一输入输出约定。

上述结论先记录在 A 的数据说明中，再据此同步相关共享说明，避免不同成员使用不同数据口径。

## 三、阶段任务与验收标准

### 阶段 1：数据收集与理解（第 1 周）

- [x] 获取所选数据，按仓库约定存放于 `data/`，原始文件保留不覆盖。
- [x] 整理字段字典：字段名、含义、类型、取值、缺失或特殊值说明。
- [x] 检查样本量、重复记录、空值、`unknown`、类别分布、数值范围及目标正负比例。
- [x] 记录质量问题及处理建议；重复记录先判断含义，再决定是否删除。
- [ ] 统一 Python 版本、依赖、相对路径与随机种子，向 B 提供原始数据读取方式。

**验收**：数据来源可追溯，版本和规模已核实；B 可按统一路径读取数据；字段字典和质量检查结果可供报告引用。

### 阶段 2：预处理与初版交接（第 1 周完成初版）

- [x] 编写 `code/01_preprocessing.py`，提供清晰的入口和可复用处理函数。
- [x] 对真正缺失值与 `unknown` 分别制定策略，说明保留、填补或删除的理由。
- [x] 检查年龄、通话时长、联系次数等数值字段，区分合法极端值、错误值和业务特殊值。
- [x] 对无序类别优先考虑 One-Hot 编码，并约定新类别的处理方式。
- [x] 提供数值标准化方案，支持逻辑回归等模型；与 B 确认树模型的处理需求。
- [x] 将 `y` 映射为固定的二分类标签，明确正类为订阅客户。
- [ ] 固定训练集与测试集划分；初步建议采用分层 80% / 20%、`random_state=42`，经三人确认后固定。

**验收**：同一输入和配置得到一致划分；输入输出样本对应关系清楚；每项处理有理由；预处理器仅在训练数据上拟合。

### 阶段 3：特征工程与实验支持（第 2 周）

- [ ] 根据 B 的 EDA 结论共同确定特殊值处理、分箱及派生特征，逐项记录定义和适用数据版本。
- [ ] 明确 `duration` 的实验使用口径；若用于通话前预测，主实验排除该字段，可另设对照实验。
- [x] 准备原始分布基线、SMOTE、欠采样和类别权重的配置方式，供 B 对比。
- [ ] 与 B 确认混合类别数据的采样方案，避免对类别编码机械插值；必要时评估 SMOTENC 等适配方式。
- [x] 使用 Pipeline 或等效机制，使填补、编码、缩放与采样在各交叉验证训练折内完成。
- [ ] 协助 B 运行实验，记录数据版本、特征方案、采样策略、随机种子及运行配置。
- [x] 保持测试集原始类别分布，禁止对测试集采样或用测试集选择处理策略。

**验收**：B 可在一致划分上开展模型与不平衡处理对比；各方案可追溯；训练、验证和测试之间不存在拟合或采样泄漏。

### 阶段 4：代码整合与交付（第 3 周）

- [ ] 整合 A 的预处理、B 的 EDA / 建模及 C 的评估脚本，核对执行顺序、路径和接口。
- [x] 补齐根目录 `requirements.txt`，记录已验证的 Python 和依赖版本。
- [x] 更新根目录 `README.md`：数据准备、安装依赖、运行命令、输出位置和常见问题。
- [x] 完成 `docs/A/数据预处理说明.md`，覆盖策略、方法、理由、处理前后统计及局限。
- [ ] 在全新环境按 README 完成一次端到端复现，记录命令、环境、结果和发现的问题。
- [ ] 与 B、C 交叉检查代码和文档，修复问题后向 C 交付代码包及报告可引用材料。
- [ ] 汇总 A 的 AI 使用过程、人工核验方式和实际贡献，交给 C 汇总。

**验收**：他人取得数据和代码后可按文档完成全流程；依赖齐全、路径无个人机器绑定；所有报告引用的预处理结论与实际代码一致。

## 五、与 B、C 的交接约定

### 向 B 交接

首次交接至少包含：原始数据定位方式、字段字典、标签映射、固定划分、预处理调用方式、配置和已知限制。保留原始数据用于 EDA，同时提供可纳入交叉验证的预处理接口，避免仅交付在全部训练集上预先拟合的矩阵用于调参。

所有划分保留稳定的样本标识（可使用原始行索引）及其对应关系。记录特征名和顺序，使 B 后续输出预测结果、概率及特征重要性时可与原始样本、处理后的特征对应。

### 向 C 交接

提供可直接引用的数据规模、字段说明、预处理方法和理由，以及代码复现记录、A 的工作量说明和 AI 使用记录。与 B、C 共同确认测试集标签与预测行顺序一致，正类和概率含义一致。

### 变更规则

数据版本、划分、特征定义或标签映射一旦变化，需记录原因并同步 B、C；受影响实验重新运行。遵守仓库的独立分支及组长合并约定，共享文件修改前做好组内协调。

沿用原计划三周节奏，具体起止日期由 C 统一排期；A 的代码包内部交付应早于最终截止，为报告定稿与复现预留时间。

| 时间 | 关键产出 | 主要依赖 |
|---|---|---|
| 第 1 周 | 数据版本核对、字段字典、质量检查、预处理初版和首次交接 | 三人确认数据与预测场景 |
| 第 2 周 | 特征方案、固定划分、不平衡处理接口和实验支持记录 | B 的 EDA 反馈及建模接口 |

| 风险 | 处理方式 |
|---|---|
| 数据版本、规模或特殊值解释混用 | 阶段 1 核对实际文件与对应说明，统一后再开始实验 |
| `duration` 与预测时点冲突 | 明确预测场景，记录主实验和对照实验的字段范围 |
| 全量拟合预处理或提前采样导致泄漏 | 先划分，再在训练集或交叉验证训练折内拟合与采样 |
| 特征工程与建模接口反复变化 | 尽早交接最小可用版本，固定接口并记录后续变更 |
| 环境、路径或数据缺失导致无法复现 | 使用相对路径，明确数据获取步骤，在全新环境验证 |
