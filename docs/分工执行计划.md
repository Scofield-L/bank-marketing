# 数据挖掘大作业 · 三人分工执行计划

> 选题：**Bank Marketing（银行营销预测）** —— 预测客户是否订阅定期存款（二分类）
> 数据：UCI Bank Marketing Data Set，当前默认 bank-full.csv，45,211 条，16 个特征 + 1 个目标变量
> 组员：3 人（成员 A / 成员 B / 组长 C）
> 周期：3 周，截止 **2026.11.30** 前提交至「延河课堂」

---

|------|----------|----------|----------------|-----------|

| **成员 B** | 算法 / 建模 | EDA + 建模 + 调参 | ②探索性分析、③建模（选算法+实现） | **报告技术章节 + 建模代码** |

## 二、成员 A —— 数据与预处理（主责提交物：程序代码）

### 具体工作清单

- [ ] **1. 数据收集**：下载 Bank Marketing 数据集（当前默认完整文件 `bank-full.csv`），核对数据量约 45,211 条（≥5000 ✅），记录数据来源 URL 与字段说明。
- [ ] **2. 数据理解**：阅读字段说明，按所选版本确认字段（bank-full 为 16 个输入特征）和目标变量 `y`（取值 `yes`/`no`），整理字段含义表。
- [ ] **3. 缺失值/unknown 处理**：检查 `job`、`education`、`marital` 等类别字段中的 `unknown` 值，设计处理策略（删除 / 填充众数 / 单独标记为 `unknown` 类别），并写明理由。
- [ ] **4. 异常值处理**：检查数值型特征（`age`、`duration`、`campaign`、`pdays`、`previous` 等）的异常值，决定是否处理及方法。
- [ ] **5. 类别编码**：对类别特征做编码（One-Hot / Label Encoding），记录编码方案。
- [ ] **6. 数值缩放**：对数值特征做标准化 / 归一化，说明为何需要。
- [ ] **7. 类别不平衡处理**：计算正负样本比例（正例约 11%），准备 SMOTE / 欠采样 / 类别权重三种方案，供 B 做对比实验。
- [ ] **8. 数据划分**：`train_test_split` 划分训练集 / 测试集，固定 `random_state` 保证可复现。
- [ ] **9. 代码整合**：统一代码结构与命名、添加注释、编写 `README.md` 与 `requirements.txt`，保证他人可一键复现。

### 具体提交物

| 提交物 | 说明 |
|--------|------|
| `01_preprocessing.py`（或 notebook） | 数据预处理完整代码 |
| `数据预处理说明.md` | 预处理策略 + 方法 + 每步理由（供报告直接引用） |
| **完整项目代码包** | 含 `README.md`、`requirements.txt`、所有脚本，可一键运行 |

## 三、成员 B —— EDA 与建模（主责提交物：报告技术章节 + 建模代码）

### 具体工作清单

- [ ] **1. 探索性分析（EDA）**：目标变量分布（正负占比）、数值特征直方图、类别特征 vs 目标变量的条形图、相关性热力图、关键特征（`duration`、`campaign`、`previous`）深入分析。
- [ ] **2. 特征工程**：根据 EDA 发现做特征构造 / 选择（如 bank-full 的 `pdays=-1` 处理；additional 版本才使用 999、年龄分箱、派生特征）。
- [ ] **3. 基线建模**：构建逻辑回归（LR）作为基线模型，得到初始指标。
- [ ] **4. 模型扩展**：依次实现决策树（DT）、随机森林（RF）、XGBoost。
- [ ] **5. 不平衡处理实验**：对 SMOTE / 欠采样 / 类别权重做对比，记录效果差异。
- [ ] **6. 调参**：用 GridSearchCV / RandomizedSearchCV 对最优模型调参。
- [ ] **7. 模型产出交接**：输出各模型的测试集预测结果、预测概率、特征重要性、模型对象，**交给组长 C 做评估与结果可视化**。
- [ ] **8. 创新注明**：若有自定义/改进实现（如集成策略、自定义特征），在代码和报告中明确标注。

### 具体提交物

| 提交物 | 说明 |
|--------|------|
| `02_eda.py`（或 notebook） | EDA 可视化代码 |
| `03_modeling.py`（或 notebook） | 建模 + 调参代码 |
| 模型产出（预测结果/概率/重要性） | 交接给组长 C |
| 报告技术章节草稿 | "探索性分析" + "数据挖掘"两章 |

## 四、组长 C —— 统筹、评估、可视化与汇报（主责提交物：报告 + PPT + 视频）

### 具体工作清单

- [ ] **0. 组长统筹**：制定三周进度表并跟踪推进、组织组会、把控 deadline、协调组员间任务衔接、处理突发问题。
- [ ] **0. 技术路线牵头**：组织确定技术路线并执笔写入报告。
- [ ] **0. 最终定稿与提交**：整合各成员成果、统一排版、终稿审核、按时提交至延河课堂。
- [ ] **1. 评估方案设计**：确定评估指标（准确率、精确率、召回率、F1、AUC、PR-AUC），并论证"为何不能只看准确率"（类别不平衡场景）。
- [ ] **2. 评估代码实现**：编写 `04_evaluation.py`，对 B 交接的各模型结果计算评估指标、生成评估矩阵 / 对比表。
- [ ] **3. 结果可视化**：绘制 ROC 曲线、PR 曲线、混淆矩阵、模型对比柱状图、阈值调优曲线（对应要求③"可视化数据挖掘结果"）。
- [ ] **4. 评估结论**：给出最终推荐模型及推荐理由，形成评估章节。
- [ ] **5. AI 工具使用汇总**：汇总三人全程使用 AI 工具的过程与作用，形成报告"AI 工具使用"章节。
- [ ] **6. 报告统筹撰写**：汇总 A/B 内容，撰写完整报告（任务、数据、工具、技术路线、分工、各阶段成果、成员工作量）。
- [ ] **7. PPT 制作**：制作汇报 PPT（问题定义、技术路线、数据、方法、结果、评估、总结）。
- [ ] **8. 视频录制**：录制讲解视频（按 PPT 顺序讲解）。
