# 人机边界（人机分工）

> 项目：Bank Marketing 银行营销预测 —— 预测客户是否订阅定期存款（二分类）

| CRISP-DM 阶段 | 学生核心任务 | AI 可辅助内容 | 大模型高频风险 |
|---------------|--------------|---------------|----------------|
| 业务理解 | 明确"客户是否订阅定期存款"的业务内涵；界定电话营销业务目标与评价标准（召回率优先，减少无效骚扰、提升营销转化） | 搜集银行电话营销/存量客户经营背景资料；整理字段业务含义 | 混淆"订阅定期存款"与其他理财产品购买行为的差异；直接套用通用分类框架，忽略电话营销场景特点 |
| 数据理解 | 梳理 16 个输入字段的业务分类（客户属性/营销交互/宏观指标）；制定数据质量研判思路；识别 `unknown` 值、`pdays=-1` 特殊标识、逻辑矛盾与业务型异常值 | 初步检测缺失/异常值；生成数据分布统计与可视化代码辅助理解 | 直接删除 `unknown` 样本、忽略"未填写"的业务语义；忽略 `duration` 字段的"事后性"（预测时点不可知） |
| 数据准备 | 确定缺失/异常值的业务处理规则；完成编码选型与业务驱动特征衍生（`pdays` 分箱、接触次数聚合等） | 生成数据清洗、编码转换、特征构造代码 | 仅靠统计指标筛选特征、忽略业务可解释性；把 `duration` 等"泄漏未来信息"的字段直接入模 |
| 模型构建 | 确定候选模型池（LR/DT/RF/XGBoost）与不平衡处理方案（SMOTE/欠采样/`class_weight`）；确定以 PR-AUC/AUC 为主的调优目标；设计对比实验框架 | 单模型训练、网格/随机搜索调参代码编写 | 在数据划分前做 SMOTE 造成训练测试泄漏；只优化准确率、忽略召回率业务诉求 |
| 模型评估 | 兼顾技术指标（AUC/PR-AUC/F1）与业务指标（召回率、误报成本）；确定阈值调优策略；给出选型结论 | 输出混淆矩阵、指标计算、ROC/PR 绘图代码 | 只报技术指标、跳过业务有效性验证；不平衡场景仍以准确率为准误导结论 |
| 结果部署 | 客户订阅倾向群体划分；设计差异化营销跟进策略；撰写分析报告与汇报 | 报告文字润色、格式排版、PPT 辅助生成 | 生成脱离银行营销现实的策略、缺乏可落地性 |
